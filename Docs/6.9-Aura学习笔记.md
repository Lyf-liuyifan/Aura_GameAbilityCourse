# 6.9 学习笔记（基于当前 Aura 工程代码）

> 依据仓库内实际实现整理，便于复习与对照视频。路径均以 `Source/Aura/` 为根。

## 1. 本章核心在做什么

- **Gameplay Ability System（GAS）**：把「属性、效果、复制」从角色里拆到 **PlayerState + ASC + AttributeSet**，角色只持有引用并做 `InitAbilityActorInfo`。
- **UI 与属性解耦**：用 **WidgetController** 监听 ASC 属性变化，通过 **动态多播委托** 通知蓝图 Widget（血条/蓝条等）。
- **环境效果**：用 **EffectActor** 在重叠时施加 `GameplayEffect`，离开时按策略移除（典型：火圈持续伤害）。

## 2. GAS 在你项目里的数据流

### 2.1 组件放在哪：`AAuraPlayerState`

- 文件：`Public/Player/AuraPlayerState.h`、`Private/Player/AuraPlayerState.cpp`
- 在构造函数里：
  - `CreateDefaultSubobject<UAuraAbilitySystemComponent>`
  - `CreateDefaultSubobject<UAuraAttributeSet>`
  - `AbilitySystemComponent->SetIsReplicated(true)`
  - `SetReplicationMode(Mixed)` — 常见 RPG 配置，效果/属性在客户端也可预测展示。
- 实现 `IAbilitySystemInterface::GetAbilitySystemComponent()`，供系统查询 ASC。

### 2.2 角色如何接上 ASC：`AAuraCharacter::InitAbilityActorInfo`

- 文件：`Private/Character/AuraCharacter.cpp`
- **服务端**：`PossessedBy` → `InitAbilityActorInfo`
- **客户端**：`OnRep_PlayerState` → `InitAbilityActorInfo`（PlayerState 复制到位后再初始化）
- 流程要点：
  1. `GetPlayerState<AAuraPlayerState>()` 取 PS（可能首帧为空，你这里用 `if (!AuraPlayerState) return` 避免 `check` 崩）。
  2. `ASC->InitAbilityActorInfo(PlayerState, Character)` — **Owner / Avatar** 配对。
  3. 把 PS 上的 ASC/AS **Cast** 到角色成员 `AbilitySystemComponent` / `AttributeSet`（类型与接口返回一致）。
  4. 取 `AAuraHUD`，调用 `InitOverlay(...)` 把 **PC、PS、ASC、AS** 传给 UI 层。

### 2.3 属性定义：`UAuraAttributeSet`

- 文件：`Public/AbilitySystem/AuraAttributeSet.h`、`Private/AbilitySystem/AuraAttributeSet.cpp`
- 使用 `FGameplayAttributeData` + `ATTRIBUTE_ACCESSORS` 宏生成 Getter/Setter/Init。
- 构造函数里 `InitHealth / InitMaxHealth / InitMana / InitMaxMana` 给**默认值**。
- `GetLifetimeReplicatedProps` 里对属性 `DOREPLIFETIME_CONDITION_NOTIFY(..., REPNOTIFY_Always)`，配合 `OnRep_*` 里 `GAMEPLAYATTRIBUTE_REPNOTIFY`，保证复制与 GAS 属性通知链正确。

## 3. UI：HUD → OverlayWidget → WidgetController

### 3.1 参数打包：`FWidgetControllerAttributeParams`

- 文件：`Public/UI/WidgetController/AuraWidgetController.h`
- 结构体携带：`PlayerController`、`PlayerState`、`AbilitySystemComponent`、`AttributeSet` 指针，供 Controller 基类保存。

### 3.2 HUD 创建与初始化顺序：`AAuraHUD::InitOverlay`

- 文件：`Private/UI/HUD/AuraHUD.cpp`
- 顺序（很重要）：
  1. `CreateWidget` 出 Overlay 主界面 `UAuraUserWidget`
  2. `GetOverlayWidgetController`：若不存在则 `NewObject`，`SetWidgetController(WCParams)`，再 **`BindCallbacksToDependencies`**
  3. `OverlayWidget->SetWidgetController(WidgetController)` — 让蓝图侧能拿到 Controller 并绑 UI
  4. **`BroadcastInitialValues()`** — 把当前属性**立刻推一遍**给 UI（否则血条会从默认 0 开始，直到第一次属性变化才更新）
  5. `AddToViewport`

### 3.3 Overlay 控制器：`UAuraOverlayWidgetController`

- 文件：`Public/.../AuraOverlayWidgetController.h`、`Private/.../AuraOverlayWidgetController.cpp`
- **委托**：`DECLARE_DYNAMIC_MULTICAST_DELEGATE_OneParam(...)` 生成的类型名与成员类型必须一致（你当前为 `FOnHealthChangedSignature` 等）。
- **`BroadcastInitialValues`**：对 Health/MaxHealth/Mana/MaxMana 各 `Broadcast` 一次当前值。
- **`BindCallbacksToDependencies`**：
  - `ASC->GetGameplayAttributeValueChangeDelegate(GetXxxAttribute()).AddUObject(this, &UAuraOverlayWidgetController::XxxChanged)`
  - 回调参数为 `const FOnAttributeChangeData&`（头文件需 `#include "GameplayEffectTypes.h"`），成员函数**不要**多余末尾 `const`，否则与 `AddUObject` 成员指针签名不匹配。
  - 回调里 `OnXxxChanged.Broadcast(Data.NewValue)` 把变化推到蓝图。

## 4. 环境伤害：`AAuraEffectActor` 与 GameplayEffect 策略

- 文件：`Public/Actor/AuraEffectActor.h`、`Private/Actor/AuraEffectActor.cpp`
- **应用策略** `EEffectApplicationPolicy`：Instant / Duration / Infinite 各自可选 `ApplyOnOverlap`、`ApplyOnEndOverlap`、`DoNotApply`。
- **移除策略** `EEffectRemovalPolicy`：对 Infinite 默认 `RemoveOnEndOverlap`。
- **`ApplyEffectToTarget`**：
  - 用 `UAbilitySystemBlueprintLibrary::GetAbilitySystemComponent(Target)` 取目标 ASC。
  - `MakeOutgoingSpec` → `ApplyGameplayEffectSpecToSelf`，得到 `FActiveGameplayEffectHandle`。
  - **关键**：若为 **Infinite** 且 **`RemoveOnEndOverlap`**，必须把 `ActiveEffectHandle` 与 `TargetASC` 记入 `ActiveEffectHandles`，否则 `OnEndOverlap` → `RemoveEffectFromTarget` **找不到任何 Handle**，表现为离开火区仍持续伤害/GameplayCue 声效。
- **`RemoveEffectFromTarget`**：遍历 map，匹配同一 `TargetASC` 的 handle，`RemoveActiveGameplayEffect` 后从 map 删除。

## 6. 易错点速查（你代码里已踩过或已修）

| 现象 | 常见原因 |
|------|-----------|
| 委托类型编译报错 | `DECLARE_...` 第一个参数名 必须与 成员变量类型名 **完全一致** |
| `AddUObject` 匹配失败 | 回调签名需与委托一致；`FOnAttributeChangeData` 需包含正确头文件；避免错误 `const` 成员函数 |
| `TEXT` 宏参数过多 | `UE_LOG` 格式串只在 `TEXT("...")` 里，变量在逗号后：`UE_LOG(..., TEXT("v=%f"), x);` |
| `TObjectPtr` 返回裸指针 | `return Ptr.Get();` |
| 血条初始为 0 | 未在 `BroadcastInitialValues` 里广播 **当前** Health/Mana（你已补全） |
| 离开火仍受伤/有声 | Infinite GE 的 Handle 未在 `RemoveOnEndOverlap` 路径登记，导致无法移除（你已改为在 `RemoveOnEndOverlap` 时 `Add`） |
| `PlayerState` 空断言 | `PossessedBy` 早于 PS 就绪；用判空 + `OnRep_PlayerState` 再初始化 |

## 8. 与「只跟视频」时的差异提醒

- 视频里类名/委托名可能与仓库不一致（例如 `UOverlayWidgetController` vs `UAuraOverlayWidgetController`），以 **你工程里 `DECLARE` 与 `UCLASS` 实际名字** 为准。
- `Build.cs` 里加 `GameplayAbilities` 只解决**链接/包含路径**，不能替代头文件里的 `#include` 与前向声明。
